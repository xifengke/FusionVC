# 运行条件、数据使用与资源边界

## 测试集已经使用

最终测试文件已按固定官方对象版本下载，完整文件CRC32C校验通过并记录SHA256。
本地评分覆盖170,846个细胞、18,080个基因、100个未见扰动，含38,176个对照细胞。
在访问测试表达前已冻结27个 checkpoint 与一次无扰动对照；所有28次评价均已完成。

因此，本项目不能写成“因为内存不够，没有下载或使用测试集”。
早期文档保留的“留到最终阶段下载”是实验顺序安排，已由后续完成记录更新。
**不把大文件提交到源码仓库，不等于没有使用这些大文件。**

证据：[测试下载记录](test-download-status.json)、[冻结清单](final-model-selection.json)、
[最终测试报告](../results/final-test/README.md)、[完成核验](project-completion-verification.json)。

## 已记录的硬件与实现选择

全量实验环境为 Windows、Python3.12、PyTorch2.8.0+cu128、RTX4060 Laptop GPU，显存8GB。
系统RAM最低要求和跨硬件最低配置未测定。没有把未经记录的OOM或系统内存不足当作已发生事实。

| 资源或范围选择 | 实际做法 | 解释边界 |
| --- | --- | --- |
| GPU预算 | 冻结基础编码器，离线提取表示，只训练较小预测头 | 未运行全参数微调；不能断言所有微调方案都无法在8GB运行 |
| 特征与序列范围 | 训练对照拟合的34维描述、256候选输入、2,048个提取对照 | 输出仍为全部18,080基因；没有全细胞gene-level embedding全量缓存 |
| 训练开销 | 有限批量、bf16预测头与float32表达变换/损失 | 资源折中也是实验范围选择，不代表更大预算下的上限 |
| 系统内存与I/O | 稀疏数据分块读取、磁盘float32缓存和内存映射 | 下载不要求整份矩阵同时驻留RAM；未测量RAM下限 |
| 评分磁盘开销 | 共享真实参考，串行评分，每次清理临时预测 | 不同时保留所有模型的完整预测矩阵 |

这些措施共同服务于可运行的本机实验。冻结、候选输入限制和未做的大规模搜索并非仅由资源决定，也涉及项目定位及实现范围。

## 已知磁盘开销

以下为十进制GB，部分值为约数，不等于峰值RAM或GPU占用。

| 文件或缓存 | 规模 |
| --- | ---: |
| 训练原始h5ad | 约15.48GB |
| 验证原始h5ad | 约6.93GB |
| 测试原始h5ad | 11.95GB |
| 训练细胞MMD缓存 | 约16.00GB |
| 测试float32真实表达缓存 | 约12.36GB |
| 一个测试临时预测矩阵 | 约12.36GB，评分后清理 |
| Student演示包 | 约26.3MB，含256个训练对照子集 |

仅新增完整测试阶段的原始文件、真实缓存和一个预测矩阵就约36.7GB；最终脚本还保留18GB磁盘余量。
这不是整个项目的最低磁盘要求，还需训练/验证数据、其他缓存、环境、来源模型和checkpoint等空间。
早期80–90GB预算是当时规划，不是后来全部文件的实际总占用或复现保证。

下载还受网络吞吐影响；下载器支持固定版本、分块续传与校验。网络连接失败与OOM是不同问题。

## 发布包与本机工作区的区别

源码发布包包含代码、配置、依赖说明、图表、逐靶点成绩与来源清单。
默认不包含 `data/`、`models/`、`vendor/`、`outputs/`、虚拟环境、安装缓存或论文PDF。
论文、数据、模型和第三方源码通过各自来源取得，不随本项目重新许可。

Student权重与对照子集同样不默认打进源码包。没有推理包时，不能直接执行示例得到已有模型的预测。
可以在完整训练后自行导出；后续若单独提供推理产物，应说明来源、适用条款、包校验和及与正式评分控制库的区别。
